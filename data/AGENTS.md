# AGENTS.md — Generated data

This directory contains machine-generated, disposable indexes. Repository-level `AGENTS.md` still applies.

## General rule

Generated files under `data/` must never become the only source of truth for user-authored knowledge or manual decisions. They must be rebuildable from Knowledge Cards, repository configuration, model/generator code, and human-owned overrides.

Do not hand-edit generated indexes to express user intent.

## `embeddings.json`

- Generated by `npm run embeddings:build`.
- Stores semantic vectors, content hashes, provider/model identity, and dimensions by stable Card ID.
- Unchanged Card/model inputs should reuse cached vectors during normal incremental runs.
- `--full` may intentionally rebuild all vectors.
- Human corrections never belong in this file.
- Before committing generated embeddings, run `npm run embeddings:validate`.

## `relations.json`

- Generated by `npm run relations:build` or `npm run relations:build:semantic`.
- May contain taxonomy/semantic/LLM scores, typed edges, direction, reasons, pipeline metadata, and cached classifier decisions.
- Must not become the source of truth for Knowledge Card metadata.
- Human relation decisions belong in `config/relation-overrides.yaml`.
- Valid cached LLM classifications should be preserved when inputs are unchanged; an unavailable API must not silently downgrade them during a full rebuild.
- Avoid timestamp-only rewrites when material inputs and outputs are unchanged.
- Before committing a relation index change, run `npm run relations:validate` and `npm test`.

## `concepts.json`

- Generated by `npm run concepts:build` from current Knowledge Cards and `config/concept-config.yaml`.
- Stores canonical Concept nodes, Card↔Concept mappings with evidence/strength, Concept↔Concept co-occurrence edges, and graph statistics.
- Category Concepts and supported shared-tag Concepts are derived mechanically; promoted higher-order Concepts are defined by repository-owned rules in `config/concept-config.yaml`.
- Concept membership is generated evidence, not a manual annotation store. Do not hand-edit mappings or Concept relations in this file.
- Concept IDs become public routes under `/concepts/<id>`; generator/config changes must preserve stable IDs unless an intentional migration is being performed.
- Before committing Concept index changes, run `npm run concepts:validate` and `npm test`.

## Generated commits

Automation may commit `data/embeddings.json`, `data/relations.json`, and `data/concepts.json`. Generated-data commits must not modify `content/knowledge/` or repository/human-owned config as a side effect.

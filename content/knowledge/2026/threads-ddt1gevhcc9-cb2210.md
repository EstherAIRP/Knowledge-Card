# PetPetAgent 對話畫布：AI 對話分岔與工作階段合併

## 一句話介紹

這是一個以畫布管理 AI 對話分岔的工具概念：使用者可以從任一既有分岔點繼續對話，也能把兩個感興趣的對話工作階段（session）合併後交給 AI 代理（Agent）繼續，讓原本線性的聊天紀錄變成可選取、可重組的上下文。

## 它解決什麼問題

一般聊天介面雖然能保留完整歷史，但當對話中途延伸出支線後，使用者常需要回頭尋找先前的分岔點。來源貼文指出，這時很容易不知道應該回到哪一個對話氣泡繼續，尤其對話變長、支線變多後更明顯。

PetPetAgent 的切入點是把這個問題從「在長聊天紀錄裡回捲尋找」改成「在畫布上選擇要延續的節點」。來源還進一步描述跨工作階段合併：可把兩個既有對話中感興趣的內容合併後提供給 Agent，再基於這些先前結果繼續推進。

## 核心概念

1. **非線性對話管理**：對話不再只是一條時間線，而是具有可回訪分岔點的結構。
2. **從任意節點續聊**：使用者可直接選擇想繼續的分岔口，而不是重新複製前文或手動尋找聊天位置。
3. **跨工作階段上下文組合**：兩個既有對話可以被重新組合成新的 Agent 上下文。
4. **把中間結果當作可重用素材**：來源以計算過程中的中間結果作比喻，強調先前對話結果可被帶入新的推進路徑。

從功能設計來看，這等於把「哪些歷史內容要進入模型上下文」從聊天介面的隱性行為，轉成使用者可操作的顯性結構。這是根據來源功能做出的設計推論，不代表來源已公開內部資料模型或提示詞組裝方式。

## 架構與技術

來源貼文沒有公開程式語言、前後端框架、模型供應商、儲存方式或對話合併演算法，因此不能據此判定實際技術棧。

依公開功能可以整理出一條**概念性資料流**：

```text
既有對話工作階段
→ 在畫布上選擇分岔點
→ 單一路徑續聊
   或選擇兩個工作階段
→ 組合可用上下文
→ 交給 Agent
→ 產生新的延伸對話
```

其中最關鍵但來源未說明的實作細節包括：

- 如何選取與排序合併後的訊息；
- 是否保留原始 system / developer / tool 訊息層級；
- 對話過長時如何處理 token 上限；
- 是否會摘要、去重或解決互相衝突的上下文；
- 對話資料保存於本機、雲端或其他服務；
- 支援哪些模型與供應商。

## 主要功能

- **畫布式對話管理**：用視覺化畫布呈現並管理 AI 對話。
- **分岔點續聊**：可以從任一想繼續的既有分岔點重新展開對話。
- **兩個工作階段合併**：可把兩段感興趣的對話工作階段合併後交給 Agent 延續。
- **重用先前答案**：將已經得到的中間答案當成後續推理或討論的輸入。
- **提供下載入口**：來源貼文指向 `petpetagent.com` 供有興趣的使用者下載試用。

## 技術亮點

### 1. 把對話歷史變成可操作的上下文圖

線性聊天通常把歷史紀錄當成單一序列。畫布式介面則能把「哪一段歷史屬於目前分支」呈現成更清楚的結構，降低長對話中的定位成本。

### 2. 讓上下文組合成為使用者操作

兩個工作階段合併的價值不只是介面便利，而是把「上下文組合」提升成一級功能。若後續實作能保留來源節點、順序與提示詞層級，這種做法可延伸到研究筆記、需求探索、Agent 協作與長期專案對話。

### 3. 適合需要反覆探索的 Agent 工作流

對於會頻繁產生支線、比較不同方案或保留多個假設的任務，畫布比單一路徑聊天更容易保存探索過程，也更適合作為之後重新組合上下文的入口。

## 限制與風險

目前來源只有一則短篇功能介紹，因此成熟度與實作品質仍有大量未知資訊。

- **合併語意不明**：兩段對話若包含互相衝突的指令、假設或角色設定，系統如何排序與解決衝突尚未說明。
- **上下文膨脹**：直接合併多段歷史可能快速增加 token 使用量，是否有摘要、裁切或重要度選擇機制未知。
- **提示詞層級風險**：若把舊工作階段內容直接重組進新上下文，需要避免把歷史中的一般文字誤當成高優先級指令。
- **來源追溯**：合併後若看不出每段內容原本來自哪個工作階段，可能降低可解釋性與除錯能力。
- **隱私與儲存方式未知**：來源沒有說明對話資料如何保存、同步或傳輸，也未提供隱私與安全細節。
- **工程資訊不足**：目前未從來源取得版本、授權、支援平台、模型相容性、公開文件、基準測試或原始碼資訊，因此不應把它視為已完成技術審查的成熟框架。

## 與你的相關性

依公開技術背景，這項工具與 **LLM / Agent** 的關聯最高。它直接碰到長對話中的上下文管理、分岔與重組問題，適合作為 Agent 介面與對話狀態設計的參考。

對 **SillyTavern / AI RPG** 也有明顯參考價值：角色對話與劇情探索經常出現平行支線，如果能保留不同分岔並在需要時重組上下文，會比單純複製聊天紀錄更接近「可編輯的敘事狀態」。

對一般 AI 研發而言，它比較像互動模式與上下文工程的產品設計案例，而不是已公開演算法或研究方法；AOI 與影像生成的直接關聯則較低。

## 建議怎麼使用

### TRY

來源已提供下載入口，值得直接體驗實際的分岔、回溯與工作階段合併操作，重點觀察：

- 分岔在資料結構上如何呈現；
- 合併兩段對話後，模型實際收到哪些歷史內容；
- 長對話是否會摘要或裁切；
- 新分支是否保留與原節點的追溯關係。

### REFERENCE

即使不直接導入，也值得把它當成「非線性聊天介面 + 使用者可控上下文組合」的產品設計參考。若未來設計 Agent 工作台、AI RPG 對話管理或研究型聊天介面，這種模式比單純增加聊天搜尋更值得比較。

在進一步整合前，仍應先確認官方文件中的資料儲存、隱私、模型支援、授權與上下文合併規則。
